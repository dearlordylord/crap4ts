# Uncle Bob crapper: TypeScript comparison

Review date: 2026-10-03. Upstream revision: [`9f1bead298b5a9d576bdd6319289fcf426e5b18a`](https://github.com/unclebob/crapper/tree/9f1bead298b5a9d576bdd6319289fcf426e5b18a). Local revision: `b088eabad90d6ea5394c4e069d2f224eaa65e20c`, including the existing working tree. Method: inspected pinned upstream source and local source; no upstream suite or comparative benchmark was run. This supersedes the earlier attribution question: `unclebob/crapper` is a real multi-language tool with TypeScript support, distinct from `sebassdc/crap4ts`.

## Useful gaps, in priority order

1. **Branch coverage as an explicit scoring option.** Upstream retains LCOV `BRDA` counts and uses branch coverage whenever records fall within a function's line span, otherwise line coverage. Local LCOV validates those records but scores line hits. Branch coverage can distinguish executing a conditional from exercising its alternatives. Add an opt-in basis, preserve existing defaults, and expose the actual basis and fallback in reports; silently changing existing scores would break threshold expectations. Upstream's attribution is line-based, so same-line and nested functions still require care. Sources: [upstream coverage.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/coverage.py), [local LCOV](../crates/crap4ts-core/src/coverage/lcov.rs).
2. **Optional-chain decisions.** Upstream counts `?.`, including property, indexed, and optional-call forms. Local complexity counts logical expressions (already including `??`) and logical assignments, but has no optional-chain increment. Consider counting each optional segment, with a documented rule and compatibility decision because CRAP scores change. Sources: [upstream typescript.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/languages/typescript.py), [local source.rs](../crates/crap4ts-core/src/source.rs).
3. **Readable route labels.** Upstream turns inline Express-style callbacks into entries such as `GET /users`, disambiguating additional callbacks with `#2`, and handles `.route(path).get(...)`. Local already extracts callback functions and isolates their complexity; the improvement is labels and route metadata, not discovering previously invisible callbacks. Upstream recognizes member names rather than proving the receiver is an Express router, so borrowing its heuristic indiscriminately can label unrelated `.get()` calls as routes. Sources: [upstream typescript.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/languages/typescript.py), [local collector](../crates/crap4ts-core/src/source.rs).
4. **Changed-file convenience.** Upstream `--changed` reads Git status and selects current files, including untracked files, restricted to the analysis root. This is useful for local feedback. It is not a PR base comparison: committed changes disappear from Git status. A local version should distinguish working-tree changes from an explicit base reference. Source: [upstream cli.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/cli.py).

## Conditional or lower-priority additions

- **JavaScript support:** upstream also discovers `.js/.jsx/.mjs/.cjs`; local accepts `.ts/.tsx/.mts/.cts`. Useful for mixed repositories, conditional on intended product scope. Sources: [upstream discover.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/discover.py), [local source.rs](../crates/crap4ts-core/src/source.rs).
- **Coverage runner detection:** upstream selects an existing `coverage` script, Vitest, or c8 around npm test, per nearest package. Local already supports configured generation commands and coverage groups, so this is convenience rather than missing generation. Upstream may install coverage tools into `node_modules` and restores manifests afterward; prefer explicit setup guidance or an opt-in mode. Sources: [upstream runners.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/runners.py), [local generation.rs](../crates/crap4ts-cli/src/generation.rs).
- **Complexity-only mode:** upstream `--no-coverage` reports coverage and CRAP as unavailable. This is convenient before test instrumentation exists. Source: [upstream analyze.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/analyze.py).
- **EDN export:** `.metrics/crap.edn` uses namespace/name identities for uml-viewer. Add only if that integration matters; local versioned JSON is already a machine-readable contract. Source: [upstream metrics.py](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/metrics.py).

## Behavior to retain locally

Upstream omits ordinary nested declarations/arrows as separate entries and charges non-route nested callbacks to their enclosing function. Local's independent function units and exclusive coverage attribution are more suitable for precise per-function reports. Upstream missing coverage becomes numerical 0%, including failures that leave no usable report; local's explicit unknown state and stricter enforcement preserve the distinction between untested code and unavailable evidence. Retain those contracts while borrowing usability improvements. Sources: [upstream extraction](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/languages/typescript.py), [upstream analysis](https://github.com/unclebob/crapper/blob/9f1bead298b5a9d576bdd6319289fcf426e5b18a/src/crapper/analyze.py), [local coverage](../crates/crap4ts-core/src/coverage.rs), [local application](../crates/crap4ts-core/src/application.rs).

Recommendation: investigate branch-based scoring and optional-chain complexity first; add route labels and changed-file selection as reporting/workflow improvements. No evidence here supports replacing the current parser, attribution, or gate model.

Review date: 2026-10-02. Local revision: `9a93f7e61f004867c6f4c0af9101c3366d8ce3cd` (existing working-tree changes were preserved). Alternative reviewed: [`sebassdc/crap4ts`](https://github.com/sebassdc/crap4ts/tree/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc), revision `340d0e2c62fad70dcf737b8a479cf1b058d1d9fc`, package version 0.1.1.

## Repository identity

There is no publicly accessible `unclebob/crap4ts` at review time: [GitHub repository API](https://api.github.com/repos/unclebob/crap4ts) returned 404 and `git ls-remote https://github.com/unclebob/crap4ts.git HEAD` reported repository not found. The first two pages of the [public repository listing](https://api.github.com/users/unclebob/repos?per_page=100) contain `crap4clj`, `crap4go`, `crap4java`, and `crapper`, but no `crap4ts`. This cannot rule out a private or renamed repository.

The public TypeScript implementation found was `sebassdc/crap4ts`; its [README](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/README.md#inspiration) explicitly credits Uncle Bob's `crap4clj` as inspiration. The comparison below is with that implementation, not code owned by Uncle Bob.

## Method

Read the alternative's source and tests in an isolated clone at `/tmp/crap4ts-sebassdc-review`. Ran `npm ci --ignore-scripts`, `npm test`, and `npm run build`. Used direct Node probes against the compiled public modules to inspect edge cases. No production source was modified. Local implementation observations were checked against source and the parent review's test results.

## Alternative's useful capabilities

- Public TypeScript API (`generateReport`, extraction, coverage, formatting helpers), enabling direct library use: [api.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/api.ts).
- Text, JSON, Markdown, and CSV output; top-N display while checking all rows; CRAP, complexity, and minimum-coverage thresholds: [report.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/report.ts), [options.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/options.ts).
- Automatic config discovery (`crap4ts.config.json`, `.crap4tsrc.json`), configurable coverage command, runner detection, coverage subprocess timeout (default 600 seconds), bundled agent skill installation: [config.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/config.ts), [report.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/report.ts), [skill-cmd.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/skill-cmd.ts).
- TypeScript compiler AST rather than regex analysis. Actual source discovery supports `.ts` and `.tsx`, despite README claiming `.tsx` ignored: [core.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/core.ts).

## Correctness findings and reproduced examples

1. **Missing coverage becomes full coverage.** `analyzeFile` substitutes empty maps when a source has no matching coverage entry; `coverageForRange` returns 100 when there are no matching statements. Direct probe `coverageForRange({statementMap:{},s:{}},1,4)` returned `100`. Thus an uninstrumented file or coverage-path mismatch can pass the coverage gate. [core.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/core.ts), [coverage.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/coverage.ts).
2. **Line-only overlap mixes distinct functions and enclosing statements.** Two statements on line 1, one covered and one uncovered, returned `50%` for both function ranges `(1,1)`, even when their column ranges differ. Statement ranges overlapping parent/child functions are counted repeatedly. [coverage.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/coverage.ts).
3. **Nested functions disappear entirely.** `extractFunctions('function outer(){ function inner(x){ if(x) return 1; return 2; } return inner(0); }')` returned only `outer`, complexity 1. Nested bodies are skipped during complexity traversal and extraction scans top-level statements only. README's claim that nested complexity is attributed to the enclosing function contradicts implementation. Also unrecognized: class-field arrows, anonymous default function declarations, class expressions, namespace-contained functions, and object-property arrows. [complexity.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/complexity.ts).
4. **Overload signatures become phantom rows.** `function f(x:string):string; function f(x:string){return x;}` produced two rows named `f`, each complexity 1. Functions without bodies are not excluded. Parser diagnostics are not inspected either. [complexity.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/complexity.ts).
5. **Explicit CLI defaults cannot override config.** Parsing `--src src --output text --timeout 600`, then merging `{src:'lib',output:'json',timeout:120}`, resulted in `lib`, `json`, and 120 seconds. Explicit presence is lost and merge compares values to defaults. Unknown flags such as `--fail-on-crapp` are accepted as source filters, rather than usage errors. [config.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/config.ts), [options.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/options.ts).
6. **Validation and error recovery can hide problems.** Coverage validates only that `statementMap` and `s` are objects, not their locations/counts; config is cast without field validation. `analyzeFile` catches any exception, prints a warning and skips the file; an empty report is allowed to pass. Source traversal follows directory symlinks without cycle protection. [coverage.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/coverage.ts), [config.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/config.ts), [core.ts](https://github.com/sebassdc/crap4ts/blob/340d0e2c62fad70dcf737b8a479cf1b058d1d9fc/src/core.ts).

## Comparison with this repository

The local Rust/Oxc core provides broader symbol extraction and `.ts/.tsx/.mts/.cts` support, exclusive attribution of nested statements, UTF-16 Istanbul column conversion, explicit unknown-coverage states and strict default enforcement, and a strict LCOV adapter. Its CLI adds exact per-path thresholds, independent monorepo coverage groups with preflight validation, deterministic versioned JSON schemas, and direct argument-array generation commands that delete only the selected artifact. These are meaningful correctness and CI-contract improvements over the alternative: [source.rs](../crates/crap4ts-core/src/source.rs), [coverage.rs](../crates/crap4ts-core/src/coverage.rs), [application.rs](../crates/crap4ts-core/src/application.rs), [config.rs](../crates/crap4ts-cli/src/config.rs), [generation.rs](../crates/crap4ts-cli/src/generation.rs).

The alternative is more convenient for JavaScript library embedding, human-friendly CSV/Markdown exports, top-N reports, minimum coverage gates, and automatic runner/config discovery. Its timeout is a worthwhile local feature gap. Neither implementation uses branch coverage weighting, counts optional chaining as decisions, or counts parameter-default decisions in the function body's cyclomatic complexity. Rust alone is not evidence of higher speed; no comparative benchmark was run.

## Validation and limits

Alternative: build passed. Tests: **307 passed, 2 failed, 309 total** in 16 files. Failures were `tests/skill-cmd.test.ts` project installation path equality and `tests/report.test.ts` minimum-coverage gate. Both involve macOS `/var` versus `/private/var` path identity; the second is operationally significant because a missing path match becomes 100% coverage. This run does not establish test outcomes on Linux or Windows. `npm ci` reported nine dependency advisories, but exposure was not audited and these counts are not used as a runtime-security conclusion.

Local validation reported by parent review: npm wrapper/script checks passed (6 wrapper tests and 19 script tests). `cargo test --workspace` exposed an existing macOS CLI test failure: `absolute_source_inside_project_root_is_accepted`, because an absolute temp source under `/var` triggers ancestor symlink rejection (`symlink directory '/var' is not allowed`). Core tests passed (35 unit and 10 LCOV), CLI unit tests passed (15), and CLI integration tests passed 47/48. Coverage generation uses `child.wait()` without a timeout. This limits any claim that our current tree is fully green or fully portable.

## Conclusion

Do not replace the local implementation with the alternative: for reliable quality gates, the local coverage and symbol model is materially stronger. Borrow selected usability features, starting with coverage-process timeout and convenient report exports/library access. Address the local macOS absolute-path rejection before calling the implementation cross-platform complete. The attribution should remain precise: the reviewed TypeScript project is sebassdc's, inspired by Uncle Bob; a public Uncle Bob-owned `crap4ts` was not found.
